# 图片知识入库设计

版本 1.0，2026-10-16。本文为图片知识功能的实现契约；首期只支持 Windows 桌面端，图片仍由 Electron 主进程管理。

## 目标与边界

图片知识需要同时满足三个条件：用户能回看原图，检索能命中可读文本，回答能回到原图中的证据位置。图片本身不能成为唯一的知识表示，也不能让视觉模型直接生成未经确认的事实。

首期支持 PNG、JPEG、WebP、GIF 首帧和常见扫描页图片。PDF、视频、手写长文档和批量相册作为后续能力；不把它们悄悄当作普通文本导入。

## 数据模型

`documents` 继续保存标题、分类、标签和可检索 Markdown。新增迁移 `004_document_assets.sql`，建立以下表：

| 字段 | 作用 |
| --- | --- |
| `id` | 资源 UUID，引用时不暴露本地路径 |
| `document_id` / `document_revision` | 与笔记版本绑定，编辑后旧提取结果自动失效 |
| `sha256` | 内容寻址和重复上传去重 |
| `mime_type`、`byte_size`、`width`、`height` | 解码后确认的媒体属性 |
| `storage_key` | userData 下的相对路径，禁止保存任意绝对路径 |
| `ocr_text`、`vision_summary` | 两条独立提取通道，不能互相覆盖 |
| `quality` | `pending`、`confirmed`、`needs_review`、`failed` |
| `ocr_confidence`、`text_coverage` | 质量门禁和 UI 解释依据 |
| `created_at`、`processor_version` | 审计和可重复处理 |

二进制文件放在 `userData/assets/<sha256 前两位>/<sha256>`，不放进 PostgreSQL 的 `bytea`，也不把 base64 塞进 Markdown。数据库只保存元数据和提取文本；备份导出时可选择“带原图”或“仅文本”。

## 处理流水线

1. **主进程预检**：通过文件头确认 MIME，拒绝伪造扩展名、未知格式、动画 GIF、多余的 EXIF 路径和超过 10 MiB 的文件；解码后限制最长边 12,000 像素、总像素 40 MP。
2. **安全保存**：计算 SHA-256，写入临时文件并 fsync，再原子 rename 到内容寻址目录。重复 sha256 只增加引用，不重复保存。
3. **规范化副本**：按 EXIF 方向旋转，生成最长边 2,048 像素的预览图；原图保持不变，预览只用于 UI 和视觉模型，避免把超大图直接发送到网络。
4. **提取文本**：文档类图片先走 OCR；表格、流程图、界面截图再走视觉摘要。两者都返回区域坐标、页/帧号和置信度，不能只返回一段无来源的长文本。
5. **合并为 Markdown**：标题、用户描述、OCR 原文和视觉摘要分区保存；每个区域生成稳定的 `asset_id` 和 `bbox` 标记，供来源对话框定位。
6. **质量门禁**：OCR 置信度、文本覆盖率、图像清晰度或视觉响应 schema 任一低于阈值，状态设为 `needs_review`，只保存原图和草稿，不进入向量 generation。
7. **人工确认**：用户在预览中校对文本、旋转或删除错误段落；点击确认后才创建索引任务。确认后的文本仍保留处理版本和原始 OCR，方便追溯。

## 防止模型识别错误

- **证据分层**：回答上下文默认只使用 `confirmed` 文本；`needs_review` 内容只能在用户明确打开“包含待校对图片”后参与，并在引用中显示警告。
- **高风险区域**：数字、金额、日期、代码、药品名、表格单元格和专有名词要求 OCR 二次处理或人工确认；视觉摘要不能改写这些字段。
- **结构化校验**：视觉 provider 输出必须符合严格 schema（区域、文字、描述、置信度），越界坐标、重复区域、超长文本和不可解析 JSON 直接失败。
- **提示约束**：模型提示明确要求“只描述可见内容”“不猜测模糊文字”“无法确认时返回 unknown”，并把 OCR 与视觉摘要标记为不同来源。
- **可回看引用**：每个回答引用同时展示缩略图、原图打开按钮、提取文本和区域坐标；用户能在原图上核对模型回答。
- **失败可恢复**：OCR 空结果、视觉超时、API key 缺失或图片损坏时保留原图，显示可操作的失败原因和手动描述入口，不生成假的索引内容。

## UI 与 IPC

导入对话框增加“图片”入口，支持多选、缩略图、旋转和删除。每张图显示“待识别 / 待校对 / 已确认 / 失败”状态；文本校对区使用 16px 正文和 18px 阅读预览，按钮、输入框和缩略图均保留 `no-drag`，符合 [Designlang.md](../Designlang.md)。

主进程新增最小 API：`pickImageFiles`、`assets:inspect`、`assets:process`、`assets:confirm` 和 `assets:open`。API 只接收窗口拥有的资源 ID，不接收 renderer 任意路径；`assets:open` 通过受限的 `knowledge://asset/<id>` 协议提供只读内容。所有请求/响应复用 Zod schema，并沿用现有 owner、origin、取消和字节上限检查。

## 索引与搜索行为

确认后的 OCR/视觉文本按普通 Markdown 分块，chunk 元数据带 `asset_id` 和区域范围。关键词检索可直接命中 OCR，向量检索使用确认文本；RRF 和 Cohere Rerank 不改变来源 ID。图片没有确认文本时，搜索结果只显示资源卡片，不把图片当成可回答证据。

## 测试门禁

- 文件头与扩展名不一致、超大文件、超像素图片、EXIF 旋转、透明 PNG、动画 GIF、重复 sha256。
- OCR 低置信度、空结果、表格数字、混合中英文、手写模糊、provider 超时和非法 JSON。
- 断电/进程退出发生在临时文件写入时，不能留下可被引用的半文件；删除笔记不能留下可访问的资源。
- 只有确认文本创建索引任务；编辑确认文本后旧 generation 不得继续命中新内容。
- 真实 Electron 测试验证沙盒、路径穿越、Windows ADS、跨重启资源可读性、预览与原图一致性；真实 provider eval 使用显式预算和合成图片。

首期不把“模型看过图片”当成成功条件。成功条件是原图可回看、提取结果可解释、低质量输入可阻断、用户可以校对并且引用能回到证据区域。
